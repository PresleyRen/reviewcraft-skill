# 从证据到全文与每一段

## 先形成一个能说清的论证

```text
读者的问题
  → 现有综述解释到哪里
  → 本文的比较单位与新增综合
  → 检索/提取为什么能回答问题
  → 各子问题的跨研究发现
  → 冲突、边界与替代解释
  → 对研究或工程的具体影响
  → 有证据的结论
```

每项中心结论填写“问题→来源→比较条件→综合→支持范围”。没有证据的内容进入待办或明确的研究建议，不先写成结论。分类框架应由问题和材料迭代形成，不能为了看起来完整强迫每篇进入预设类别。

## 章节安排按功能选择

常用骨架是Introduction→Foundations/Related reviews→Review method→Synthesis→Implications/Agenda→Limitations→Conclusion。目标期刊可以要求不同结构，不机械套IMRaD或固定章数。

| 部分 | 应完成的工作 | 检查问题 |
|---|---|---|
| 标题/摘要 | 范围、研究类型、方法、主要综合及用途 | 是否超过实际覆盖？摘要数字与主文是否一致？ |
| 引言 | 具体问题、读者需求、最近邻不足和贡献 | 是否把“热门”当成缺口？新增认识是否具体？ |
| 基础/相关综述 | 定义会改变比较的概念，区分已有综合 | 是否重复介绍常识？是否公平保留前人成果？ |
| 综述方法 | 可重建的搜索、纳排、版本、提取、复核和综合 | 报告的是已做还是计划？未知项如何处理？ |
| 主要综合 | 围绕问题横向比较来源、解释异同 | 是否逐篇流水账？同名指标的条件是否相同？ |
| 讨论/建议 | 解释发现、替代解释、具体用途与下一步 | 建议是否能追溯？分析例子是否冒充实测？ |
| 局限 | 会改变读者理解的具体范围和证据缺口 | 是否在承认后又忽略其影响？ |
| 结论 | 回答研究问题及保留的贡献 | 是否引入新主张、口号或泛化？ |

## 每段的最小逻辑卡

在工作记录中为每段给稳定ID，填写：

```text
P-ID / 章节：
段落要完成的一个主要功能：
接住前一段的哪个问题：
核心论断与必要条件：
所用证据及原文定位：
本段增加的比较/解释：
要交给下一段的问题（若有）：
重复/缺证据/语义风险：
```

不用规定每段必须有同样句数或显式过渡句。有时顺序、术语和主题延续已经够清楚。图能帮助检查：

```text
S1-P1 工程现象 → S1-P2 现有测试的条件 → S1-P3 本文问题
S4-P1 比较维度 → S4-P2 同条件证据 → S4-P3 边界/反例
                                     ↓
                               S5 解释选择后果
```

重复分三类：无信息重复应删；独立阅读单元如摘要/结论/图注的必要重复可留；重复但限定不同的内容需合并或明确区别。不要只凭词频判断。

## 做综合而非堆论文

按同一比较单位列：输入/条件、作用对象、信息权限、方法、参照、端点、分母、成本、证据强度与局限。可比时比较数值，不可比时解释为什么不同；不将异构排行榜平均成一个“通用能力”。

把看似矛盾的结果按任务、版本、历史信息、评分及预算拆解。区分文献报告的发现、本综述从多来源推导的综合、作者提出的建议。有效的新综述可以提供“何种证据支持何种选择”的资源，而不宣称发明来源论文的方法。

最近邻对照采用：已有概念→本稿新增证据关系→不同的理解/选择→直接来源。若没有可辨认的新增关系，回到范围与贡献，不靠加长文章解决。
