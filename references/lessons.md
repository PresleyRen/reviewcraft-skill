# 实际教训与每阶段自检

这里提炼工作方式，不公开来源项目的未发表内容、私人资料或日志。失败应变成可检验的改进，而非给每次任务增加无限流程。

| 走偏方式 | 为什么不足 | 下次采取的具体动作 | 不能走向的另一极端 |
|---|---|---|---|
| 一直扩大研究地图，迟迟不给可讨论的具体问题 | 信息量增加却没改变决策 | 从最近邻和明确失败条件形成一页问题，再做能否改变决策的核验 | 强行承诺每个想法都能录用 |
| 把已有相关研究当作停止理由 | 混淆“已有组件”和“同一问题完全解决” | 对照具体输入、输出、条件、证据与剩余增量 | 仅组合术语就宣称新方法 |
| 先写目录后找证据填空 | 预设叙事容易忽略反例 | 先建立主张—来源—比较条件，再决定结构 | 所有文献读完才允许有提案 |
| 声明有界，却不检查停止对综合的影响 | 诚实披露没有消除选择偏差 | 比较原语料与新增批次对中心判断的影响 | 无限检索到无法证明的“全领域穷尽” |
| 抽样重读只说做过，不报告发现 | 他人无法判断解释可靠性 | 保存对象、字段分母、发现与处理；新增批次单列 | 把AI共识当人工金标 |
| 反复文字修改，当前文件关系混乱 | 容易改一份上传另一份 | 一个有效主稿、同步派生件、冻结哈希 | 删除冻结证据来清目录 |
| 对“去AI味”按词表全删 | 可能删掉限定、否定、真实边界 | 逐句判断信息作用，比较改前改后语义 | 为逃检测故意引入语病 |
| 声明争议反复拉扯 | 没把用途、官方范围、具体句子分开 | 一次列条款、实际用途和各位置，处理最小差异 | 以期刊偏好掩盖真实使用 |
| 把语言审查当查重/AI检测 | 没有工具报告却暗示有百分比 | 检测单列状态；无报告就未知 | 强迫每篇购买不需要的服务 |
| 上传后才想起最终审稿 | 科学问题可能已进入正式系统 | 内容总审完成且版本一致后才能进入提交准备 | 内部审查一有建议就自动撤稿 |
| 门户上传完成就称已投稿/已外审 | 不同状态证据被混用 | 保存真实确认和回执，按阶段报告 | 反复无意义查门户或自动监控 |

## 监控技能有没有走偏

每阶段问四个问题：
1. 这一步要改变哪个研究/写作决定？
2. 输入是原文、真实记录还是助手的猜测？
3. 输出是否有可定位依据、未完成范围和反驳条件？
4. 下一步需要更多信息，还是已有信息已经足够执行？

如果几轮只有文档增多、核心判断不变，停止当前动作，回到最近的未解决决策；优先检查现有证据，不新增第二套地图/状态系统。发现问题定位规则、输入或操作错误，再做最小修正。

## 每轮给用户的简短汇报

```text
做了：读/核对/修改了哪些具体材料。
结果：哪些成立、哪些未完成；不要混淆计划与结果。
反省：这轮哪里可能走偏、如何校正。
下一步：一个明确动作，以及它要解决的疑问。
流程：输入 → 本轮动作 → 实际产物 → 下一决策。
```

不需要每次长篇教学或自我批评。没有新的错误也可以直说未发现新的流程问题。修改Skill时记录真实触发案例和一个合法反例，避免把局部教训变成无条件禁令。
